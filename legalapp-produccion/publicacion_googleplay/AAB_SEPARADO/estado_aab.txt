CUIDADO - BUG DETECTADO Y CORREGIDO (2026-07-25):
La clave "android.targetapi" que se uso originalmente en buildozer.spec NO EXISTE
en Buildozer - se ignora en silencio y Buildozer usa su default interno (33) pase
lo que pase en el .spec. La clave real es "android.api". Esto causo 2 builds
fallidos (Play Console rechazo la primera version por seguir targeteando API 33
pese a que el .spec decia 35) antes de detectarlo leyendo el codigo fuente de
buildozer/targets/android.py.
Si en el futuro hay que tocar el target API de nuevo:
1. usar "android.api = XX" en buildozer.spec, NUNCA "android.targetapi"
2. borrar la carpeta dists cacheada antes de recompilar:
   rm -rf .buildozer/android/platform/build-arm64-v8a_armeabi-v7a/dists
3. verificar el resultado real en el manifest fusionado, no confiar en el .spec:
   grep -o 'targetSdkVersion="[0-9]*"' .buildozer/android/platform/build-arm64-v8a_armeabi-v7a/dists/legalapp/build/intermediates/merged_manifests/release/processReleaseManifest/AndroidManifest.xml

- 2026-08-07: subida a android.api = 36 (Google Play paso a exigirlo). Primeros
  2 intentos fallaron con el mismo error, sin relacion con el target API:
  "ImportError: cannot import name 'BuildDependencyInstallError' from
  'pip._internal.exceptions'" dentro de la venv que python-for-android crea
  para instalar los modulos Python puros (build.py, funcion
  run_pymodules_install). La causa real: p4a (rama master) construye un
  hostpython3 en Python 3.14.2 y despues corre "pip install -U pip" adentro de
  una venv nueva; ese auto-upgrade a la ultima version de pip de PyPI dejaba
  la venv en un estado inconsistente (mezcla de versiones de pip) - probable
  cambio reciente del lado de PyPI/pip, no algo que tocamos nosotros. El
  "ResolutionImpossible" de kivymd que aparece antes en el log es un WARNING
  benigno (process_python_modules lo atrapa y sigue, no rompe el build) -
  no confundirlo con la causa real.
  Fix aplicado: en la copia local de python-for-android
  (.buildozer/android/platform/python-for-android/pythonforandroid/build.py,
  funcion run_pymodules_install, linea ~878) se cambio
  "source venv/bin/activate && pip install -U pip" por
  "source venv/bin/activate && pip --version" (se salta el auto-upgrade, usa
  el pip que ya viene con la venv nueva vía ensurepip, que anda bien solo).
  Tambien hubo que borrar a mano la venv vieja ya corrupta
  (.buildozer/android/platform/build-arm64-v8a_armeabi-v7a/build/venv) para
  que el parche tuviera efecto - si no se borra, sigue usando la venv rota
  de un intento anterior aunque el parche ya este aplicado.
  OJO: este parche es local a esta copia de python-for-android en WSL. Si se
  borra `.buildozer` entero o se clona python-for-android de nuevo, hay que
  volver a aplicar el parche (o esperar a que el bug se arregle upstream).
  4to intento (con el parche + venv vieja borrada): compilo OK,
  targetSdkVersion=36 confirmado en el manifest real. Version final (v1.1.11,
  versionCode=123).
